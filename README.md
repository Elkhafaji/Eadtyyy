# عيادتي — نظام إدارة عيادة

النسخة الحالية تعمل بواجهة HTML واحدة وخادم Node.js وقاعدة SQLite محلية دائمة. الخادم المحلي موجود في `local-server.cjs`، بينما دالة Vercel موجودة في `api/db.js`. البيانات تحفظ في `data/eyadaty.sqlite` ولا تُنشأ بيانات مرضى أو أطباء تجريبية تلقائيًا.

## التشغيل المحلي

يتطلب Node.js 22.x.

```powershell
$env:ADMIN_PASSWORD='غيّر-هذه-الكلمة-قبل-التشغيل'
$env:ADMIN_EMAIL='admin@example.com'
node local-server.cjs
```

ثم افتح `http://127.0.0.1:4000`.

للتشغيل اليومي بسهولة، اضغط مرتين على `start-eyadaty.cmd`. سيشغل الخادم تلقائيًا إذا كان متوقفًا ثم يفتح الموقع.

للتشغيل التلقائي مع Windows، اضغط مرة واحدة على `install-eyadaty-autostart.cmd` بصلاحيات المستخدم الحالي. لا تغلق عملية خادم Eyadaty أثناء استخدام الموقع؛ إغلاقها يوقف الموقع.

يتم إنشاء حساب مدير واحد فقط عند أول تشغيل لقاعدة فارغة إذا كان `ADMIN_PASSWORD` مضبوطًا. لا تضع كلمة المرور داخل ملفات المشروع ولا ترفع ملف `.env`.

## الاستضافة

شغّل `npm start` على استضافة تدعم Node.js، واضبط `PORT` و`DATA_DIR` وبيانات المدير السرية. يجب أن يكون مجلد `DATA_DIR` قابلًا للكتابة وضمن تخزين دائم؛ إذا كانت الاستضافة بلا تخزين دائم فلن تكون SQLite مناسبة، وانقل التخزين إلى PostgreSQL قبل الإنتاج.

### Vercel + PostgreSQL

المشروع يحتوي على `api/db.js` كـ Vercel Function. عند ربط قاعدة PostgreSQL في Vercel، أضف متغير `DATABASE_URL` أو `POSTGRES_URL` إلى بيئات Preview وProduction، ثم انشر المشروع. أول طلب ينشئ جدول `eyadaty_app_state` تلقائيًا. لا ترفع مجلد `data` أو أي ملف `.sqlite` إلى GitHub.

لنقل قاعدة SQLite الحالية إلى PostgreSQL بعد تثبيت الحزم وضبط `DATABASE_URL`:

```powershell
$env:DATABASE_URL='رابط-PostgreSQL-الخاص-بك'
npm run migrate:postgres
```

## ملاحظة أمنية

هذه طبقة تشغيل محلية/استضافة صغيرة تربط الواجهة الحالية بقاعدة دائمة. قبل استخدام بيانات مرضى حقيقية في بيئة عامة، أضف جلسات خادمية وصلاحيات API خادمية وHTTPS وتخزين ملفات خارجيًا آمنًا ومراجعة امتثال طبي؛ الواجهة الحالية ما زالت تستخدم نموذج مزامنة JSON واحد للحفاظ على التصميم الحالي.
